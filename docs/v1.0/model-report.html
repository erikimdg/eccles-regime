How NEON explains the frozen decision

Kauffmann et al., NEON, arXiv:1906.07633v2, section II. At an exact decision tie the service reports an undefined assigned-class LRP.

Same classifier

Squared-distance differences are linear in the transformed coordinates. A linear comparison layer and minimum pooling reproduce the original nearest-center classifier. Daily service inference has no XGBoost surrogate.

Explain one assigned class

For the selected class c, compare both other centers k. The smallest advantage is its margin f[c]. Directional LRP allocates that margin through both comparisons and then to the 26 coordinates.

Signed evidence

a[c,k,j] = (z[j] - (center[c,j]+center[k,j])/2) * 2*(center[c,j]-center[k,j]). Positive relevance supports the assigned class, negative relevance offsets it. Their signed sum equals the margin.

Interpretation choice

Beta=0.2660534496, inverse mean training margin. Alternative beta values preserve labels but change attribution. Correlated coordinates retain their overlap; economic usefulness is assessed using cases and controlled feature-removal tests.

Daily schedule

Collection is configured for 07:20, 09:20, 12:20 and 16:20 KST, Monday through Saturday. A US session is eligible after its scheduled close plus 90 minutes. Later runs retry delayed providers.

Publication contract

The API returns model version/hash, US as-of date, source snapshot identity, C0/C1/C2, closest alternative, all distances, percentiles, 26 NEON contributions and deterministic English/Korean interpretation.

Missing and revised inputs

Incomplete dates are withheld. The last valid date remains visible with source-level missing/stale status. Already-published version/date records are immutable; observed revisions are logged separately.

Model replacement

Validate a new bundle, refresh that version through the active model date, then atomically activate it. The service reads the active pointer without restart. Prior bundles and dated records remain available for rollback.

Version policy and next research

No automatic refit or automatic promotion. The adopted bundle remains reproducible.

Major version

Substantial feature additions/removals, source identities, target regime meaning or clustering geometry changes create v2.0. Keep the previous version active until the replacement has a dated comparison and an adoption decision.

Minor version

Small compatible model/interpretation changes create v1.1 and still require a new immutable bundle, reproducibility checks and a recorded comparison. Any change that alters labels is visible in the release report.

Separate service code

API bug fixes or operational changes that preserve model outputs increment the service patch version. Store both model and service versions with each result. API paths have their own /v1 contract.

Next research

Review overlapping co-movement and return families with controlled ablations. Revisit C1 naming using direction and participation. Macro selection and temporal processing remain separate experiments; v1.0 stays frozen during research.
